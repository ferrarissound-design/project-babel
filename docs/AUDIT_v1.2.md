# 独立監査（v1.1.1）の指摘4件への対応 — v1.2.0

この文書は、PROJECT BABEL v1.1.1 に対する独立監査の指摘4件について、再現・修正・回帰テスト・性能比較をまとめたもの。
数値はすべて、下の「再現用の情報」にあるファイルから読める。

## 結論

- 4件とも問題が実際に起きることを再現し、修正した。
- 正しい入力に対する解読器の出力は、開発シード 0〜19 の全35条件中31条件で、全指標が修正前と完全に同じ。
- 悪化した指標がある。開発シードで3件、評価シード（事後分析）で3件。どれも、語順の判定に「答えた割合」が 1/60 下がったもの（下の「悪化した指標」）。
- 独立初見テスト `gpt6-blind-01` の語彙は、既知語を除くと 21/21 正解（適合率 1.00）、推定対象25語の正解率・被覆率は 0.84。既知語を含めた従来の値（26/26、被覆率 0.867）より低い。独立初見テストの点数（5.0 / 10）は変わらない。
- 対応の途中で、範囲外の大きな問題を1件見つけた。単語境界のない文章では、構造の推定で誤答が正解より多い（問題記録 #34、未解決）。

## 問題ごとの再現結果と修正

### 1. 学習用と評価用データの分離（`babel/decipher/engine.py` の `sanitize_public()`）

再現（KES・シード3・LEVEL C・20文書。修正前の v1.1.1）:

| 条件 | 修正前 | 修正後 |
|---|---|---|
| 正常（train 16 / heldout 4） | 混入なし | 混入なし |
| train が全部存在しないID | **heldout 4件すべてが学習に混入**、評価0件 | 混入なし（train = 全文書 − heldout、警告あり） |
| train に存在しないIDが一部 | 混入なし | 混入なし |
| train と heldout に同じID | **その文書（d017）が学習に混入**、評価から消えた | 評価用として扱い、学習に使わない（警告あり） |
| heldout のみ指定 | **heldout 4件すべてが学習に混入**、警告なし | 混入なし（train = 全文書 − heldout、警告あり） |
| train のみ指定 | 混入なし（評価なし） | 同じ |
| split 未指定 | 全文書で学習（評価なし） | 同じ |
| 重複した文書ID | 混入なし。ただし**前の文書の中身が黙って消えた** | 名前を付け直して両方を残す（元のIDと同じ側） |

原因: 有効な train が1つもないと split 全体を空にしていて、解読器は split が空だと全文書を学習に使っていた。

修正: heldout に指定した文書は、どの組み合わせでも学習に入れない。分割の指定が完全に無効なら、分割なしとして明示的に警告する。実際に使った分割を予測の `split_used` に記録する。

### 2. 既知語を独立初見テストの正解数に含める問題（`babel/evaluate/score.py`）

再現: `gpt6-blind-01` の主張26語の内訳は、対訳から推定した語21、既知語として与えた語5（merchant・grain・give・scribe・count）。外部コーパス用の採点（語彙表だけの経路）は、26語すべてを正解に数えていた。内部テスト用の採点（トークン単位）は既知語を除外しており、2つの経路で扱いがずれていた。

修正（採点方式2）:
- `lexicon_inferred` を追加した。既知語を除き、解読器が推定した語だけで、適合率・正解率・被覆率を出す。
- `lexicon`（総合、既知語を含む）は、方式1と同じ定義で残した。
- 採点表の独立初見テストの語彙適合率は、`lexicon_inferred` で計算する。
- 方式1の採点ファイル（`attempt-NNN.json`）は上書きせず、方式2を `attempt-NNN.scoring-v2.json` に書く。

既存の外部テストの再集計:

| コーパス | 方式1：総合（既知語を含む） | 方式2：推定した語だけ |
|---|---|---|
| gpt6-blind-01 | 26/26 正解、適合率 1.00、被覆率 0.867（30語中） | 21/21 正解、適合率 1.00、正解率・被覆率 0.84（既知語5を除く25語中） |
| nax-holdout-levelA #1 | 9/10 正解、適合率 0.90 | 9/10 正解、適合率 0.90（トークン単位の採点では既知語は元から除外） |
| nax-holdout-levelC #1 | 主張なし | 主張なし |

方式1の採点ファイル、予測ファイル、予測台帳のハッシュは、再集計の前後で変わっていない。

### 3. 同じ概念が複数の文法役割に登場する問題（`babel/decipher/engine.py` の `_fit_alignment()`）

再現: `slot_of = dict(it["concepts"])` は概念名 → 役割を1対1で持つので、同じ概念が2回出ると後の役割で上書きされる。

- 「商人が商人に魚を渡した」: 主語が消え、この文は語順の集計から抜ける（票が失われる）。
- 「Zの召使いがZを打った」: 所有者のZの位置を目的語の位置として使う。所有者が主語の前に来る言語では、逆向き（OS）の票になる。

自然なコーパスではまれ（開発シードの対訳2,418文中9文）。生成器に `same_concept_rate`（行為者と同じ概念を受け手・目的語にも使う）を足して再現した。既定値0では乱数を余分に消費しないので、既存のコーパスは変わらない（4系統のハッシュで確認）。

修正: 概念ごとに役割の一覧を持つ。役割が1つならそれを使う。複数で曖昧なら、その語に付いた格接辞の学習済みの機能（`R:subject` など）で1つに絞れるときだけ使い、絞れなければ語順の集計に使わない（推測しない）。語順の集計は、格接辞の機能を学習した後の段に移した。

比較（開発シード 0〜19、3系統、対訳15%）:

| 条件 | 正しい票 | 逆向きの票 | 語順の正解 | 形容詞の語順の正解 | 語彙・語釈 |
|---|---|---|---|---|---|
| 重複なし | 1,012 → 1,013 | 120 → 115 | 59/60 → 59/60 | 25 → 25 | 同じ |
| 重複40% | 929 → 930 | 112 → 108 | 60/60 → 60/60 | 16 → 17 | 同じ |

重複40%の条件では、曖昧な役割395件のうち81件を格接辞で解決し、314件は捨てた。逆向きの票の大半は SOT 系統の自由語順（20%が OVS）によるもので、この修正の範囲外。

### 4. 単語境界のない文章での評価データの利用（`engine.py` と `segment.py`）

再現: 単語境界がないとき、train と heldout を合わせた全文書で分割モデルを作っていた。境界の実験（E9）も、全文書をまとめて分割・採点していた。

修正:
- 分割器を「学習」と「適用」に分けた。
- `segmentation = inductive` を追加した。train だけで学習し、heldout には学習した頻度を凍結したモデルを当てる。
- 既定は従来の `transductive` のまま。外部コーパスの予測が黙って変わらないようにするため。使った方式は予測の `segmentation_used` に記録する。
- トランスダクティブの分割は、作り直す前後で9コーパス×2手法すべて同じ結果になることを確かめた。

比較（単語境界F1、開発シード 0〜4 × 3系統 = 15コーパス、E9）:

| 方式 | train の文 | heldout の文 |
|---|---|---|
| トランスダクティブ（従来、全文書で学習） | 0.405 ± 0.051 | 0.399 ± 0.048 |
| インダクティブ（train のみで学習） | 0.407 ± 0.052 | **0.448 ± 0.060** |
| n-gram ベースライン・トランスダクティブ | — | 0.391 ± 0.047 |
| n-gram ベースライン・インダクティブ | — | 0.387 ± 0.048 |

heldout ではインダクティブの方が良かった。普通は、評価する文も学習に入れるトランスダクティブの方が有利になるので、予想と逆。仮説は「ユニグラム法は頻出する文字列を1語にまとめる癖があり（問題記録 #16）、全文書での再推定でその癖が自己強化される」だが、検証していない。

解読器全体での比較（開発シード 0〜4 × 3系統、各15コーパス、構造6項目の判定）:

| 条件 | 構造の正解 / 誤答 / 保留 | 語彙 正 / 誤 |
|---|---|---|
| LEVEL A・トランスダクティブ | 9 / 18 / 63 | 2 / 0 |
| LEVEL A・インダクティブ | 9 / 20 / 61 | 5 / 2 |
| LEVEL C・トランスダクティブ | 6 / 10 / 74 | 0 / 0 |
| LEVEL C・インダクティブ | 6 / 13 / 71 | 0 / 0 |

分割の精度ではインダクティブが良いが、解読器全体では構造の誤答がわずかに多い。15コーパスしかないので、この差が本物かどうかは分からない。どちらの方式でも誤答が正解を上回っている（問題記録 #34）。

## レビューで見つかった、この修正自体の欠陥

Codex の自動レビュー（PR #4）で、v1.2.0 の修正に欠陥が2件見つかった。どちらも再現して直した（問題記録 #35）。

- インダクティブ分割が、train にも heldout にもない文書の文字列を分割の学習に使っていた。分割の学習を解読器の学習対象（`train_ids`）と同じ文書に揃えた。
- 重複IDの付け直しで、元からある ID（例: `x#dup1`）と衝突し、その文書の中身を消していた。付け直す名前が既存のIDと重ならないようにした。

生成器のコーパスには未割り当ての文書も重複IDもないので、上の比較表の数値は変わらない。回帰テストは2件追加し、全89件が通過する。

## 研究上の限界と未解決の問題

- **#34（未解決）：** 単語境界のない文章では、構造の推定で誤答が正解より多い。分割の精度が F1 0.4 程度しかないのに、構造を主張してしまう。この監査対応の範囲外で、直すには事前登録と開発シードでの検証が別に要る。
- **推測しない方針のコスト：** 同じ概念が複数の役割に出る文で格接辞から役割が絞れないとき、その語を語順の推定に使わない。格接辞のない言語では、この種の文から語順の証拠が得られない。
- **単語分割の既定：** 既定はトランスダクティブのまま。研究計画の「train だけで学習」に当たるのはインダクティブ方式で、その結果は E9 に別の指標として載せている。
- **インダクティブの方が heldout で良かった理由：** 未検証。heldout は1コーパス13文書と小さく、ばらつきも大きい。
- **評価シードの再利用：** 評価シード 200〜219 は v1.1.0 で既に見ているので、今回の比較はすべて事後分析。v1.2.0 をまっさらな条件で評価するには、新しい評価シードが要る。
- **独立初見テスト：** 第三者のコーパスは `gpt6-blind-01` の1件だけ。採点方式2での語彙の被覆率は 0.84 だが、1件の結果で一般化は言えない。
