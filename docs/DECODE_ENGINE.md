# 解読エンジン v2：設計、失敗の原因、性能

`babel/decode/` は、旧方式（`babel/decipher/engine.py` の対応付け、PR #31 の A〜E）を置き換える役割推定のエンジンである。
旧エンジンは残してあり、既存の機能・テストはそのまま動く。v2 は `python -m babel decode` で呼ぶ。
数値は [DECODE_V2_RESULTS.md](DECODE_V2_RESULTS.md)、評価の手順は [PREREG_DECODE_V2.md](PREREG_DECODE_V2.md)。

## 1. 旧方式が実在言語で失敗した原因（調査結果）

調査はすべて PR #31 の開発側（70% の記事）で行った。最終側は使っていない。

| 問い | 分かったこと | 根拠 |
|---|---|---|
| 正しい語彙候補が消える原因 | **データの希薄さに対して、語彙の共起だけを入口にした設計**。1 言語あたり SVO のそろった文は 213 文。英語の述語 138 種のうち 102 種（74%）、目的語 181 種のうち 160 種（88%）、主語 154 種のうち 126 種が 1 回しか出ない。1 回しか出ない概念は、共起の EM では文中のどの語とも区別できない | 開発 seed0 で A の述語の回収 182/2730（6.7%）、主語 595、目的語 278 |
| 固定閾値 0.25 の影響 | 0.25 は症状。拡散した事後確率は正解にも誤りにも等しく低く、閾値を下げると候補と誤答が同じ割合で増える | PR #31 の C：候補 2.5 倍、正解 8→18、誤答 154→279 |
| IBM Model 1 の限界 | 位置・語の種類・形態をまったく使わないので、1 回しか出ない語の対応は原理的に決まらない。双方向の事後確率の積は、さらに拡散を強める | 上の回収率 |
| 品詞推定の誤り | 旧エンジンの N/V の推定は対訳と独立に決まり、その誤りが対応を禁止した（PR #30、#31 の H1）。v2 では品詞を別段階で決めず、役割の潜在変数と同時に推定する | — |
| 長文・複数節に弱い原因 | 「最初の位置」を役割ごとに選ぶので、反復語や別の節の語を組み合わせた。v2 は 3 役の組を同時に、述語からの距離と「跨ぐ語」の特徴つきで選ぶ | 開発の例：`el equipo de transición utilizó` で `transición` を主語にする誤りは、跨ぐ語の専門家で減った |
| 訓練データが減ると正解が消える原因 | 共起の回数がそのまま根拠なので、文を減らすと 2 回出ていた語が 1 回になり候補から消える | — |
| 人工言語で成功し実在言語で失敗した原因 | 合成言語は語彙が小さく（概念が何度も出る）、語形が規則的で、対訳の概念がそのまま表層の語に 1 対 1 で出る。実在言語の新聞・百科の文は語彙が大きく、主語の脱落・斜格の目的語・複合述語が多い | 開発 es で、確信度 0.8 以上の誤答の約半数は、対象文に直接の nsubj–VERB–obj が存在しない文だった |

## 2. v2 の設計

各文に潜在変数 (s, v, o)（主語・述語・目的語の位置。主語と目的語は「表出しない」も取れる）を置き、次の専門家の積でスコアを付ける。
すべての数は **leave-one-out**：その文自身の前回の寄与を引いてから、その文を推定し直す（1 回しか出ない概念が自分を確証できない）。

| 専門家 | 内容 | 1 回しか出ない語に効くか |
|---|---|---|
| 役割の分布的特徴 E_r | 頻出の前後の語・2 語先、語末 1〜3 字、語頭 1〜2 字、推定した接辞、長さ、頻度帯、文中の相対位置。背景に対する尤度比（naive Bayes、重み 0.5） | 効く（語の種類で汎化する） |
| 語彙 L（順方向） | P(語幹 \| 概念)/P(語幹)、背景へ平滑化。未知の対は 1（中立） | 2 回以上出る概念だけ |
| 語彙（逆方向） | P(概念 \| 語幹)/P(概念)。多くの別々の概念を吸い込む語（機能語）を罰する。**これが EM の退化（述語＝冠詞）を止めた** | 効く（罰として） |
| 配置 D_r | 述語からの符号つき距離（±1,2,3,4–5,6–8,9+）と「表出しない」 | 効く |
| 跨ぐ語 X_r | 項と述語の間にある語の特徴の尤度比（冠詞や前置詞は跨ぎやすく、動詞は跨ぎにくい） | 効く |
| 非表出率 | 主語・目的語の概念ごと、述語の概念ごとの「表出しない」率（代名詞の脱落、斜格） | 一部 |
| 一致 | 英語の時制と述語の語末、英語の単複と項の語末 | 効く |
| 固有名詞・借用語のアンカー | 下記 | 効く（表音文字で名前を共有する言語だけ） |

事後確率は O(n²) で厳密に計算する（3 重の総当たりと一致することをテストで確かめた）。EM は文の処理順を変えて 3 回走らせ、
三つ組の事後確率の平均を確信度とする。

### 固有名詞・借用語のアンカー（`anchors.py`）

解読の古典的な入口（カルトゥーシュの王名、地名）を、公開データだけで行う。英語の概念の文字列と、同じ文の対象の語の
記号列を位置ごとに数えて記号↔英字の対応を初期化し、EM で育てる（各概念は文中の 1 語か NULL を選ぶ）。
誤検出を防ぐために三重の対照を置いた：

1. 対訳を 7 文ずらして **アンカーモデル全体を学習し直し**、その最良スコアの 99% 点を下回るものは採らない（学習による水増しが両側で同じになる）。
2. 文字対応表を、その（概念, 語）の対を除いて計算し直してから採点する（leave-one-out）。
3. 同じ対が何度出ても、文字対応表の学習には 1 回だけ数える。

開発中、1 と 2 が無かった版は、英語と名前を共有しない合成言語でも「servant≈durakor」のような誤ったアンカーを確信度 1.0 で
出していた。ノイズだけの文字列で 200 件中 24 件が通ることをテストが検出し、1 を「学習し直す」形に直した。

### 確信度の較正（`calibration.py`）

役割モデルの事後確率は naive Bayes の積で過信になる（開発側で事後確率 0.9 以上の正解は約 3 割）。
公開情報だけから作る 22 個の数（三つ組の事後確率、再起動の一致、次点との差、各役割の周辺確率、非表出の確率、
文の長さ、距離、語彙の裏付けの量、アンカー、概念の出現量、対訳の文数）でロジスティック回帰を開発側だけで学習する。
採点の正解は較正器の学習にだけ使い、推論時には読まない。

### 出力（`schema: babel-decode-v2`）

- `structure`：語境界（与えられた／教師なしで推定）、接辞の位置と頻出の接辞、役割ごとの手がかり、項の配置。
- `lexicon`：対訳から裏付けのある語幹↔概念。
- `anchors`：学習した記号↔英字の対応の数、確度の高い対、偶然の水準。
- `word_order`：主張した組からの述語の位置の票と二項検定。足りなければ判定不能。
- `sentences`：対訳つきの文ごとに、役割の候補（周辺確率）、非表出の確率、三つ組、確信度、再起動の一致、根拠の数、主張／判定不能と理由。
- `structural_hypotheses`：対訳のない文への構造の仮説（`basis: "structure"`、概念を持たない）。
- 同じ内容の Markdown レポート（`*.md`）。
