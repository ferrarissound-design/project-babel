## 3. 解読できない原因の分離（人工データでの答え）

- **データ不足**: 正解の転写でも、13行で発見した規則は平均 4.50/8、30行で 5.17/8。構造解析の評価（results/structure/benchmark-eval.json、文字列で入力、シード 1000〜1009）では regular の100行で平均 5.00/8。行を増やすと増えるが、30行と100行の差は小さい（残りは構造解析の限界）
- **構造解析の限界**: 正解の転写・30行でも見つからない規則がある（格接尾辞・接尾辞の置換可能性。docs/ISSUES.md #41, #45）。これは画像認識と無関係
- **画像認識の誤り**: 13行で、正解の転写 4.50 → 既存の認識 1.65 → 改善した認識 3.35。認識の誤りは発見を減らすだけでなく偽の仮説を作る（font では別の字形の誤統合、stroke では分割の破片から。第2節）

人工データでは3つの要因を分けて測れる。**実画像では、正解の転写がないので分けられない**（第4節）。

## 5. 研究上の問いへの答え

「BABEL が未知文字を解読できない主な原因は、画像認識の誤りか、構造解析の限界か、データ不足か」

- **人工データ**では3つとも効いており、分けて測れた（第3節）。13行では、正解の転写でもデータ不足で規則の半分程度しか見つからない。画像認識の誤りはそこからさらに発見を減らし、存在しない記号についての偽の仮説を増やす
- **実画像では、現時点で識別できない**。正解の転写がなく、転写の統計（74クラス・1回だけ47種）は過剰な分割とも字形の多さとも両立するため
- 識別に必要な追加実験:
  1. 実画像を提供してもらい、`python -m babel vision IMG.png --out-dir v` → `python -m babel annotate IMG.png --gt gt.json --report v/glyph-report.json` で、人が13行すべての記号の枠と字形名を確認する（verified=true）。これで認識の精度（F1・ARI・分割・結合）が測れる
  2. 確認した正解の転写を `babel analyze` にかけ、認識器の転写の結果と比べる（本報告の A と B に当たる）。ここで画像認識の誤りの寄与が分かる
  3. 正解の転写でも規則が出なければ、同じ長さの正の対照（docs/STRUCTURE_RESULTS.md 表8）と比べて、データ不足か構造の欠如かを判断する。13行で検出できる規則の大きさ（detectability）を併記する
  4. 同じ文字体系の別の資料（行数を増やす）があれば、データ不足の寄与を直接測れる

## 6. 限界

- 人工画像の字形・劣化は2つの生成方式で作ったもので、実際の筆写・写真の多様さ（傾き、照明、紙の模様、手書きの揺れ）を代表しない
- 改善候補は dev の人工画像で選んだ。実画像で同じ改善が得られるかは未検証
- 構造解析への影響の実験は regular という1つの人工言語で、6シード × 2行数 × 2描画方式 × 4条件。他の言語では差が変わりうる
- 離れた部品を持つ字形の分割は、改善候補で悪化した（未解決）
