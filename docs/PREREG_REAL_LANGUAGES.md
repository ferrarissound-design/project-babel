# 事前登録: 実在言語を換字した「未知言語」での評価

この文書は、データの取得・変換のコードを書く前、解読器の出力を1件も見る前にコミットする。正解の定義・言語の選び方・採点の方法は、ここに書いたものだけを使う。

## 目的

これまでの評価は、解読器と同じAIが作った生成器・対照データの上で行ってきた（限界の1行目）。ここでは、**同じAIが設計していない言語データ**で、凍結した解読器（v1.4.0）を評価する。

- データ: Universal Dependencies（UD）のツリーバンク。リリース **r2.15** に固定する。
- 言語の文字は、無作為な1対1の文字の置き換え（換字）で隠す。解読器には記号列だけを渡す。
- 正解は、UD の注釈（品詞・見出し語）から、次の節の手順で機械的に作る。著者（AI）の言語知識で正解を決めない。

これは評価だけを行う。結果を見て解読器を変えない。変える場合は別の版として、別の言語で評価する。

## 言語（10 言語。結果を見る前に固定）

| ツリーバンク | 選んだ理由（参考。採点には使わない） |
|---|---|
| UD_Turkish-IMST | 動詞が文末になりやすい、接尾辞型 |
| UD_Basque-BDT | 動詞が文末になりやすい、接尾辞型 |
| UD_Finnish-TDT | 動詞が文中、接尾辞型 |
| UD_Hungarian-Szeged | 接尾辞型、語順が比較的自由 |
| UD_Irish-IDT | 動詞が文頭、語頭の変異 |
| UD_Welsh-CCG | 動詞が文頭、語頭の変異 |
| UD_Indonesian-GSD | 動詞が文中、接頭辞・接尾辞の両方 |
| UD_Spanish-AnCora | 動詞が文中、接尾辞型 |
| UD_English-EWT | 動詞が文中、屈折が少ない |
| UD_Wolof-WTB | 動詞が文中 |

取得できないツリーバンクがあれば、その言語は除外し、除外したことを記録する（別の言語で置き換えない）。

## コーパスの作り方

1. `*-ud-train.conllu` の先頭から、文を順に読む。複数語トークン（`1-2` の行）と空ノード（`1.1`）は使わず、構文上の語の行だけを使う。
2. 品詞 `PUNCT`・`SYM`・`X` の語を除く。語を小文字にし（Unicode NFC）、文字（Unicode のカテゴリ L・M）以外を消す。空になった語は除く。
3. 2 語以上の文だけを、先頭から **1000 文** 使う（足りなければ全部）。
4. 10 文ずつを1つの文書にする。`level: "C"`（対訳・既知語なし）、`has_word_boundaries: true`。
5. **換字**: コーパスに現れる文字を、固定の記号の集合（ラテン小文字 26 字＋ギリシャ小文字 24 字＋必要ならキリル小文字）へ、言語ごとの乱数（シード 0）で1対1に写す。
6. **対照**: 同じコーパスの語を、コーパス全体で無作為に入れ替えたもの（語の内部は本物のまま。統語だけを壊す）。

取得したファイルの SHA-256 を結果に記録する。UD のライセンスの扱いのため、ツリーバンクも換字後のコーパスもリポジトリにコミットしない。スクリプトがその都度取得して作る。

## 正解の作り方（UD の注釈から機械的に）

**動詞の位置**（`verb_position`）: 手順 2 のあとの文で、品詞 `VERB` の語がちょうど1つあり、語数が 3 以上の文を数える。その語が文頭・文中・文末のどれにあるかの割合で、最も多い位置を正解とする。最も多い位置の割合が 0.5 未満なら、その言語の動詞の位置は「明確な正解なし」とし、採点から外す（主張したかどうかだけを報告する）。

**接辞の側**（`affix_position`）: 品詞が `NOUN`・`VERB`・`ADJ` で、小文字の語形と小文字の見出し語が異なり、見出し語が 3 文字以上の語を数える。語形と見出し語の共通の頭の長さ（lcp）と共通の末尾の長さ（lcs）を比べ、lcp > lcs なら「語末が変わる」（接尾辞側）、lcs > lcp なら「語頭が変わる」（接頭辞側）、等しければ数えない。

- 接尾辞側が 75% 以上なら正解は `suffix`、接頭辞側が 75% 以上なら `prefix`、どちらでもなければ `both`。

この正解は「UD の見出し語と語形の差」であり、言語学的な「接辞」と一致するとは限らない（語頭の子音交替や語幹の母音交替も数える）。この限界は結果と一緒に報告する。

## 採点

- 各言語・各項目（動詞の位置・接辞の側）について、**正解・誤答・保留** を数える（評価できる項目の合計は最大 20）。
- 対照（語を入れ替えたもの）では、`verb_position` の主張（保留でないもの）の件数を数える。v1.4.0 は統語なしなら語順を保留するので、0 が期待値。
- 統語検定（`verdict.syntax.present`）が実コーパスで「あり」になった言語の数も報告する（実在の言語には統語があるので、検出できた割合）。
- 参考として v1.2.0（`null_gates: False`）も同じコーパスで実行して並べる。採否の判断はしない。

## 事前の予想（外れても書き換えない）

- 接辞の側は、接尾辞型の言語では多くが正解になる。語頭の変異がある言語（アイルランド語・ウェールズ語）では、正解が `both` か `prefix` になり、解読器は `suffix` と誤るか、保留する。
- 動詞の位置は、解読器が対訳なしで動詞のクラスを見つけられるかに依存し、多くが保留か誤答になる（生成器の言語より語彙が大きく、頻度が偏るため）。
- 誤答の率がどうなるかは予想できない。この評価で一番見たいのはここ。

## やらないこと

- 正解の閾値（0.5、75%）・語数（1000 文）・言語の選択を、結果を見て変えない。
- 結果を見て解読器を調整しない。
