## 1. 研究課題

限られた証拠から未知言語の「構造」と「意味」をどこまで妥当に復元できるか。
特に次の3能力を区別して測る。

1. 正しい仮説を発見する能力（構造・意味の正答率）
2. 誤った仮説を棄却する能力（競合仮説の比較、較正）
3. 解読不可能な問題を見抜く能力（判定不能の報告、過剰主張の抑制）

## 2. システム構成とデータ分離

```
babel/generator/   言語と記録文の生成（正解を保持）
babel/decipher/    解読器（generator / evaluate を import 禁止）
babel/evaluate/    採点（予測JSONと正解JSONを比較する唯一の場所）
babel/experiments/ 実験ランナー
babel/report/      ダッシュボード用JSON生成
external/          初見コーパスの投入・予測台帳・採点
docs/              GitHub Pages 静的サイト
```

分離規則（自動テストで強制する）:

- 解読器のソースは `babel.generator` `babel.evaluate` を import しない（AST 検査）。
- 生成器は `public`（解読器に渡すもの）と `secret`（正解）を別ファイルに書く。解読器の入力は `public` のみ。
- 解読器はモデルを **train 文書のみ**で構築し、held-out 文書（20%）には凍結モデルを適用する。
- シードの役割を分ける: **開発シード 0–4**（解読器の調整に使用）、**評価シード 100–119**（最終報告のみ。調整に使わない）。
- 評価シードの結果を見た後に解読器を修正した場合、その事実を記録し別試行として扱う。

## 3. 言語設計（3系統、形態・語順・数詞がすべて異なる）

| 系統 | 類型 | 語順 | 名詞 | 動詞 | 数詞 |
|---|---|---|---|---|---|
| KES | 膠着・接尾辞・母音調和 | SOV, 形容詞-名詞 | 語根-複数-格 | 語根-否定-時制-数 | 10進 |
| UMB | 接頭辞型 | VSO, 名詞-形容詞 | 格-複数-語根 | 時制-語根-数 | 20進 |
| SOT | 屈折（融合語尾・2変化類・一致） | SVO（自由語順あり） | 語根-融合語尾 | 語根-融合語尾、不規則動詞 | 12進 |

語形・接辞形はシードごとに音韻規則からランダム生成する（特定の語形をハードコードできない）。
各言語に、複合語・派生語、同音異義語、人名・地名・役職、時代による音変化・語尾変化・語彙交替、
書記ごとの表記揺れ、欠損を含める。意味表現（命題）から各文法で文を描画するため、文字置換暗号ではない。
規模: 1言語あたり約110文書・約1,100文（3言語で3,000文以上）。文書数は引数で拡張できる。

## 4. 解読条件

- LEVEL A: train 文の約5%に部分対訳（要素の約30%が欠落）。地名数個と数詞数個が既知。
- LEVEL B: 既知語6語程度＋出土地・時代・記録種別のメタデータ。対訳なし。
- LEVEL C: 文章のみ。メタデータも既知語もなし。

LEVEL C で許される主張は**内部構造**（品詞クラス、接辞、語順、数詞の相対値、合計行の機能）だけ。
実世界の意味（「この語は王」等）を1件でも主張したら過剰主張として失点とする。

## 5. 解読器の機能と比較対象

機能: 頻度分析 / 表記揺れの正規化 / 単語境界推定 / 形態素推定（パラダイム法）/ 品詞クラスと語順 /
格・活用パラダイム / 数詞（合計行の算術による連立方程式）/ 対訳アラインメント（EM）/
意味的近さ / 競合仮説と信頼度 / 逐次更新 / 解読不能性の検定（シャッフル対照）。

ベースライン: (1) 頻度のみ（頻出語尾の切り落とし、共起頻度の最大値）、(2) n-gram（文字遷移確率による分割、
隣接語ベクトル）。複雑な方法が単純な方法に勝つかどうかは**未定の仮説**であり、負けた項目もそのまま報告する。

## 6. 実験

E1 主実験（3系統×3レベル×評価20シード） / E2 ベースライン比較 / E3 データ量削減 /
E4 対訳量削減 / E5 表記揺れ・欠損耐性 / E6 未知語・未観測構造（held-out、後期時代のみの held-out）/
E7 過剰推測（無構造コーパス、語順破壊コーパス、LEVEL C）/ E8 アブレーション / E9 単語境界なし /
E10 再現性（同一シードの出力ハッシュ一致、ローカルと Actions の一致）。

簡易モード（3シード、CI用）と本格モード（20シード）を分ける。

## 7. 初見テスト（最重要）

- `external/inbox/<名前>/corpus.json`（またはUTF-8テキスト）を追加すると、固定コミットの解読器が予測を作る。
- 予測は `external/predictions/<名前>/attempt-NNN.json` に保存し、SHA-256 を `external/ledger.jsonl` に追記する。
  既存の予測ファイルは上書き不可（CIが台帳と照合）。解読器修正後の再実行は新しい attempt になる。
- 正解 `external/answers/<名前>/answer.json` が追加された後にだけ採点する。
- 同一AIが作った言語は独立な初見テストにならない。解読器凍結後に作る第4系統は
  「内部ホールドアウト（準初見）」として**別枠**で報告し、独立初見テストの点には算入しない。

## 8. 採点（100点、事前登録）

内部テストと独立初見テストは別々に報告する。未実施項目は「未評価」とし満点から除外して表示する。
数値はすべて評価シードの平均。

| 項目 | 配点 | 算出方法 |
|---|---|---|
| 実験設計・データ分離 | 15 | 自動検査5項目×3点: import分離 / public入力のみで動作 / 開発・評価シード分離 / held-out分離 / 予測台帳の改竄検査 |
| 文法・言語構造 | 20 | 形態素境界F1×5 + 接辞目録F1×3 + 品詞正解率×4 + 語順（動詞位置・接辞側）正解率×4 + 数詞（基数・値）正解率×4。A/B/C の平均 |
| 証拠に基づく意味推定 | 20 | LEVEL A: held-out語釈正解率×10 + 語彙主張の適合率×5。LEVEL B: 地名・数詞値の正解率×5 |
| 未知言語への一般化 | 15 | 内部（held-out文書、後期時代held-out）5点: 通常held-outに対する性能維持率。独立初見テスト10点: 外部コーパスが採点されるまで未評価 |
| 不確実性・解読不能性 | 15 | LEVEL C 過剰主張なし×5 + 無構造コーパス検出率×4 + 較正 (1−ECE/0.25)×3 + 証拠なし語の保留率×3 |
| 自律的な問題発見と修正 | 10 | `docs/ISSUES.md` の発見→原因→修正→回帰テストの記録。自己採点であり利益相反があるため暫定値として表示 |
| 再現性・公開 | 5 | 同一シード再現×2 + Actions とローカルのハッシュ一致×2 + Pages 公開確認×1（確認できなければ未評価） |

## 9. 既知の限界（着手時点）

- 生成器と解読器を同じAIが設計するため、解読器の事前仮定（接辞は閉じたクラス、合計行がある等）が
  生成器の設計と一致しやすい。内部テストの成績は完全な未知言語への一般化を証明しない。
- 外部LLM・有料APIは使わない。純粋なPython標準ライブラリのみ。
- 意味の正解は生成器の概念語彙に対する一致であり、実在言語の意味論の豊かさは再現していない。

## 変更履歴

## v1.1 計画（事前登録、2026-11-12、評価実行の前に記載）

### きっかけ
独立初見テスト `gpt6-blind-01`（v1.0.1、正解公開前の最初の試行）で、数詞14語がすべて判定不能だった。
原因は解読器の仮定「会計記録には合計行がある」がこの言語で成り立たなかったこと（限界として明記済みの仮定）。
`gpt6-blind-01` は結果を読んで方向を決めるだけに使い、解読器の調整・検証には使わない。

### 測り方の変更
- 開発シードを 0〜19（20個）に増やす。v1.0 の評価シード 100〜119 は結果を見たので以後の評価に使わない。
- v1.1 の評価シードは 200〜219。v1.1 の解読器を凍結するまで実行しない。
- 生成器に「合計行のない会計記録」の条件を追加する（外れた仮定を自前のデータで再現するため）。
  主実験に LEVEL A/C × 合計行なし の条件を加える。

### 解読器の変更（優先順）
1. 合計行がない場合、対訳の数量から数詞の値を解く（対訳の文ごとに「数詞語の和＝数量」の方程式）。
2. 対訳アラインメントに品詞の制約を入れる（動詞クラスの語幹は述語にだけ対応する等）。
3. 欠損の位置を使い、数詞以外の位置の欠損では会計の式を捨てない。
