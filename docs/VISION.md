# 画像からの記号抽出（ローカル実行・API不要）

この機能は未知文字の **視覚的な転写候補** を作るものです。
単語の意味、文字の読み、正しい単語境界を解読したとは主張しません。

## 使い方

既存の BABEL 本体には新しい依存関係は不要。画像解析を使う環境にだけ OpenCV と NumPy を追加します。

```bash
python -m pip install -e '.[vision]'

# 画像の文字領域を指定すると、罫線・回答欄の影響を減らせる
python -m babel vision IMG_4494.jpeg --out-dir vision-output \
  --region left:0,0,330,375 \
  --region right:337,0,670,165
```

座標は `X1,Y1,X2,Y2`（右下は含まない）。一枚の写真をそのまま入力することもできますが、
UIの枠線や図形を文字と誤認するので、文字がある領域を切り出す方法を推奨します。

この例の領域座標は 670×376 ピクセルの実験画像用です。別の画像にはそのまま使えません。

## 出力

- `glyph-report.json`: 各記号候補の座標、形状クラス番号、類似度、出現頻度、繰り返し2〜4記号列
- `glyph-annotated.png`: 元画像の上に候補の枠と分類番号を描いた画像（人間による転写点検用）
- `corpus-continuous.json`: 記号の間に単語境界がないと仮定した BABEL 入力
- `corpus-glyph-tokens.json`: 各記号を1語と仮定した**対照用**BABEL 入力

この2つは正解ではなく**相反する分割仮説**です。比較時は両方の条件を明記してください。

例：転写候補を解読器に渡す場合

```bash
python -m babel decipher vision-output/corpus-continuous.json --out vision-output/prediction-continuous.json
python -m babel decipher vision-output/corpus-glyph-tokens.json --out vision-output/prediction-glyph-tokens.json
```

画像解析だけで辞書・対訳がない場合、意味の正解率を測ることはできません。
「解読不能」は言語が無意味という判定ではなく、証拠不足の場合があります。

## 仕組みと限界

1. OpenCV の自動二値化で明るい／暗い文字を検出
2. 長い縦横の罫線を除去し、行と横方向のインクの区間を記号候補として抽出
3. 32×32 に正規化した形状の IoU と元サイズの近さで、似た候補を同じクラスにまとめる
4. 各行の視覚クラス列から2〜4記号の反復を列挙
5. 記号番号を PUA 文字に変えて、単語区切りの異なる2種類の入力を生成

**既知の限界**: 1文字が複数の独立線からできている場合は分割されることがあり、
逆に隣り合う文字が近い場合はまとめられます。回転、傾き、変形、模様、
手書き、複雑な紙面、形の似た別文字に対しては誤分類が起きます。
`glyph-annotated.png` の人間による確認が必要です。

閾値を調整する場合は `--threshold 100`、形状の類似判定を厳しくするには
`--similarity 0.8` を指定できます。閾値を変更した結果は別条件で記録してください。

**安全な研究運用**: 正解データは入力に混ぜない。画像転写は推定であることを記録し、
同じスクリーンショットで調整した結果を新しい独立初見テストとは呼ばない。
画像データはローカルで処理し、GitHubに公開する必要はありません。
