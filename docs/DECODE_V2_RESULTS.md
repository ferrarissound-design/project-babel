# 解読エンジン v2 の結果：旧方式 A〜E との比較

設計は [DECODE_ENGINE.md](DECODE_ENGINE.md)、手順は [PREREG_DECODE_V2.md](PREREG_DECODE_V2.md)。
すべて PR #31 と**バイト単位で同一の入力**（public_sha256 の一致を比較スクリプトが確かめる）と、同じ採点器 `role_recovery_score.score_predictions` による。
N は英語側に主語・述語・目的語のある文の数。主張しない文はすべて保留。正解率＝正解/N。

- 挑戦目標のうち **出力適合率 60% は達成（63.9%）、対象文の 20% に正しい構造は未達（4.4%）**。
- 誤対応（一文ずらした対訳）では v2 の主張は 7 件、正解 0。主張は対訳に依存しており、構造だけの当て推量ではない。
- 改善の大部分は固有名詞・借用語のアンカーによる（アンカーなしは 8 正解）。アラビア語・ヒンディー語・日本語・韓国語・中国語・タイ語は最終側で正解 0。名前を英語と共有しない未知の文字体系への一般化は示せていない。
- 凍結: `results/decode_v2/freeze.json`（freeze_sha256 `877e7b555ac7a7d6…`、コミット `a164bba`）。最終側の実行後にコード・閾値を変えていない。

## 安定性

- 換字 seed 0・1・2 は入力の記号を実際に変える（public_sha256 は 3 種）が、v2 の予測は 3 つとも同一だった。v2 は記号の付け替えに対して厳密に不変で、旧方式のような記号名による同点処理を持たない。したがって換字 seed は v2 の頑健性の検査としては弱い。
- EM の処理順（再起動）を 1,2,3 から 4,5,6 に変えると、開発側の生の事後確率 ≥0.5 で正解 419→413、誤答 776→765（`dev-restarts456-raw.json`）。
