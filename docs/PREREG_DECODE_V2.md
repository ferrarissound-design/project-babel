# 事前登録：解読エンジン v2（`babel/decode`）の最終比較

2026-11-23。最終側（PR #31 の記事分割の `final`）を v2 で一度も実行していない時点で、この文書をコミットする。
基点は PR #31 の `research/role-recovery-validation`（`e18fa07`）。作業ブランチは `claude/babel-decoding-engine-overhaul-12m87r`。

## 何が変わったか（設計の根拠は docs/DECODE_ENGINE.md）

旧方式 A〜E は「英語の3概念 ↔ 対象の語幹」を IBM Model 1 で先に決め、残った対応から役割を組んだ。
PUD の開発側では 1 言語あたり SVO のそろった文が 213 文、述語 138 種のうち 102 種（74%）、目的語 181 種のうち 160 種が 1 回しか現れない。
共起だけの対応付けでは大半の動詞・目的語が候補にならず、閾値・品詞制約を緩めても回収できない（PR #31 の開発 seed0 で述語の回収 182/2730）。

v2 は文ごとの潜在変数（主語・述語・目的語の位置、主語・目的語は「表出しない」も可）を、
役割ごとの分布的特徴（頻出の隣接語・2語先、接辞・語末・語頭、長さ、頻度、相対位置）、語彙（順・逆方向）、
述語からの距離、跨ぐ語の特徴、概念ごとの非表出率、時制・数との一致、固有名詞・借用語のアンカーの積で表し、
leave-one-out の逐次 EM で同時に推定する。事後確率は文ごとに厳密に計算する（O(n²)）。

## 開発データの使い方（実施済み・最終側を見る前）

- 開発側（PR #31 の dev、70% の記事）だけで設計を反復した。うち **8 言語**（es, de, ja, ru, fr, tr, zh, ar）を設計判断に使い、
  残り **11 言語**は設計判断に使っていない（開発側の中の過適合の点検として別に集計する）。
- 較正器（`babel/decode/calibration.py`、ロジスティック回帰）は開発側 19 言語・換字シード 0〜2・通常の対訳で学習する。
  性能の見積もりは言語ごとの leave-one-language-out（LOLO）とし、閾値は `babel/experiments/decode_calibrate.py` の規則で決める
  （LOLO 適合率 ≥ 0.60 かつ主張 30 件以上の最小の閾値。なければ適合率 ≥ 0.50 で正解が最多の閾値）。
- PUD 全体は既に調べた既知の資料であり、最終側も「v2 の設計に使っていない」というだけで、独立した初見評価ではない。

## 凍結

開発側の結果、較正器、`babel/decode/*.py`・`*.json`・依存する `babel/decipher/morph.py`・`segment.py` の SHA-256 を
`results/decode_v2/freeze.json` に記録してから最終側を実行する。最終側の実行後に方式・閾値・特徴を変えない。
変えた場合は「最終側を見た後の修正版」として別に報告し、初回の結果と混ぜない。

## 最終側で測るもの（この 3 つだけ。方式の選び直しはしない）

| 名前 | 内容 |
|---|---|
| v2 | 凍結した既定（アンカーあり、較正あり、3 再起動） |
| v2-no-anchors | アンカーなし（他は v2 と同じ。較正器も同じ） |
| BL-lexical | 単純な基準：構造の専門家を切り（語彙のみの EM、距離は一様）、アンカーなし、生の事後確率 ≥ 0.5 |

旧方式 A〜E は PR #31 の `results/role_recovery/final.json` の数値と比べる。入力が同一であることを `public_sha256` の一致で確かめる。
換字シード 0・1・2、通常の対訳と一文ずらした対訳、既知 19 言語の集計とガリシア語の別表示。予測をファイルに固定してから採点する。

## 指標（PR #31 の採点器 `role_recovery_score.score_predictions` をそのまま使う）

正解数・誤答数・保留数、適合率（正解/主張）、正解率（正解/英語側に3役のある全文）、誤対応での主張数と正解数、
換字シードごとの値。主張しない文はすべて保留として数え、全件保留を成功と数えない。

## 成功基準（指示書の 7 条件に対応）

1. 正解数が旧方式（A〜E のうち最良）より多い。
2. 誤答だけが増えていない（適合率が旧方式以上）。
3. 保留率を下げつつ、適合率を維持する。
4. 換字シード 0・1・2 のすべてで 1〜2 が成り立つ。
5. 合成言語ではなく実在言語で成り立つ（本比較そのもの）。
6. 開発側の調整に使っていない 11 言語と、最終側で成り立つ。
7. 既存の全テストが通る。

挑戦目標（未達なら実測値をそのまま報告する）：出力適合率 60% 以上、対象文の 20% 以上に正しい構造。
