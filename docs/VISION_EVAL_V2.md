# 画像認識の評価 v2: 評価器の最終修正・離れた部品の結合・実画像の評価の準備

このファイルは `python -m babel.vision_eval.report_v2` が results/vision/ の JSON から生成する。v1 の記録（docs/VISION_EVAL.md、results/vision/methods-*.json、impact.json）は上書きしていない。

## 1. 評価器の修正（Codex の指摘2件）

- 評価用の字形の統合（same_as）は、人が確認した項目のものだけを使う。循環・矛盾は1つにまとめて警告する（docs/ISSUES.md #66）
- 行の precision は、未確認の行に対応した予測を分母から外す。行割り当ては確認済みの行の記号だけで数える（#67）
- 人工画像の正解はすべて確認済みで same_as を使わないので、v1 の評価の数値は変わらない

## 6. 研究上の問いへの答え

「BABEL は、正しく転写された未知言語なら構造を発見できるのか。画像認識の誤りは、その能力をどれほど下げているのか」

### 人工データで示せたこと

- 正しい転写なら、設計した8規則のうち 13行で平均 4.50、30行で 5.17 を見つける（偽の仮説は少ない）。見つからない規則は、データ量（13行）と構造解析の限界（接辞・接尾辞の置換可能性: #41・#45）による
- 既存の認識の転写では、13行で 1.75、30行で 2.23（正しい転写との差 -2.75 / -2.94）
- 改善した認識 v1の転写では、13行で 3.23、30行で 3.62（正しい転写との差 -1.27 / -1.54）
- 改善した認識 v2の転写では、13行で 3.38、30行で 3.96（正しい転写との差 -1.12 / -1.21）
- 誤りの種類ごとの影響（D）: クラスの分けすぎが最も大きく発見を減らし、偽の仮説を作る。記号の誤分類10%や分割・結合10%の影響はそれより小さい

### 実画像で確認できたこと

- 残っている転写（114記号・74クラス・1回だけ47種）から、現在の構造解析で有意な仮説は1件（行3・4の類似）
- その統計は、真の字形数 20〜400 のどれとも両立し、過剰な分割か字形の多さかを転写だけでは区別できない（docs/VISION_EVAL.md 第4節）

### 現段階では判断できないこと

- 実画像の認識がどれだけ正しいか（正解転写がない）
- 実画像の文字に、人工言語のような構造があるか（正しい転写がないので、データ不足・認識の誤り・構造の欠如を分けられない）
- 人工データで測った認識の誤りの影響が、実画像の字形・劣化でも同じ大きさか（人工画像は2つの描画方式だけ）

## 7. 限界

- improved-v2 の結合の条件は「字の幅はほぼ高さ以下」という仮定に依存する。横に長い字（字の幅 > 0.95H）を持つ文字体系では、1字の中の部品を結合しきれない。逆に、細い字が密に並ぶ文字体系では、隣の字を誤って結合しうる
- 人工画像の字形・劣化は2つの生成方式で作ったもので、実際の筆写・写真を代表しない
