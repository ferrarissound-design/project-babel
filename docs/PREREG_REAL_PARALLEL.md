# 事前登録: 実在言語（Parallel UD を換字）で、対訳があるときの評価

この文書は、データの取得・変換のコードを書く前、解読器の出力を1件も見る前にコミットする。正解の定義・対訳の作り方・採点はここに書いたものだけを使う。

## 目的

v1.5.0 は、対訳による証拠があるときだけ動詞の位置を主張する（V1）。合成言語の LEVEL A では、この経路で動詞の位置の正解が 56/60 だった。**この経路が実在言語でも働くか**を確かめる。対訳があれば、対訳なしでは常に保留になる主語と目的語の順序（`so_order`）も測れる。

これは凍結した v1.5.0 の評価だけを行う。結果を見て解読器を変えない。

## データ

- **Parallel UD（PUD）**、リリース r2.15 に固定。`*_pud-ud-test.conllu`。同じ 1000 文を 20 言語に翻訳したもの。`# sent_id` が言語をまたいで対応する。
- 原文（対訳の元）: **英語**（UD_English-PUD）。
- 対象の言語: 英語以外の PUD の 19 言語（アラビア語・チェコ語・ドイツ語・スペイン語・フィンランド語・フランス語・ヒンディー語・インドネシア語・アイスランド語・イタリア語・日本語・韓国語・ポーランド語・ポルトガル語・ロシア語・スウェーデン語・タイ語・トルコ語・中国語）。
- 文字の種類が換字の記号数（82）を超える言語は除外し、除外したことを記録する（置き換えない）。取得できない言語も同様。

ツリーバンクも換字後のコーパスも、コミットしない。スクリプトがその都度取得し、SHA-256 を記録する。

## コーパスの作り方（`PREREG_REAL_LANGUAGES.md` と同じ）

対象の言語の PUD の文について、複数語トークン・空ノードを除き、品詞 `PUNCT`・`SYM`・`X` の語を除き、小文字（NFC）にして文字（Unicode のカテゴリ L・M）以外を消す。空になった語は除く。2 語以上の文だけを使う。10 文ずつを 1 つの文書にする。`has_word_boundaries: true`、`level: "A"`。文字は、言語ごとの無作為な 1 対 1 の換字（シード 0）で記号に置き換える。

## 対訳の作り方（英語 PUD の注釈から機械的に）

同じ `sent_id` の英語の文について:

1. 根（`head = 0`）の品詞が `VERB` であること。そうでなければ対訳なし。
2. 根が受動（`nsubj:pass` または `aux:pass` の子を持つ）なら、対訳なし。
3. 述語 = 根の見出し語（小文字）。
4. 主語 = 根の子で `deprel = nsubj` の語の見出し語（小文字）。目的語 = 子で `deprel = obj` の語の見出し語。見出し語が英字のみの語だけを使う。複数形（`Number=Plur`）なら `pl: true`。
5. 時制: 根の `Tense=Past` → `PAST`、`Tense=Pres` → `PRES`。それ以外は付けない。
6. 述語があり、主語か目的語が1つ以上あるものを「対訳を作れる文」とする。

対訳の形式は `external/README.md` の `translation`（`{"kind": "clause", "pred": ..., "tense": ..., "args": [{"role": "subject", "head": ...}, {"role": "object", "head": ..., "pl": ...}]}`）。

**対訳を与える割合**: 対訳を作れる文のうち、`sent_id` 順に等間隔に選んだ **10%・25%・100%**（10% は 10 文ごと、25% は 4 文ごと）。対象の言語の文が 2 語未満で除かれた場合、その文の対訳は使わない。

**対照（誤対応）**: 100% の設定で、対訳を作れる文の対訳を 1 つずつずらして割り当てる（i 番目の文に i+1 番目の対訳。最後は最初）。対訳が文と対応しないとき、解読器が語順を主張しないことを確かめる。

## 正解（対象の言語の PUD の注釈から機械的に）

- **動詞の位置**（`verb_position`）: `PREREG_REAL_LANGUAGES.md` と同じ。品詞 `VERB` がちょうど 1 つで語数 3 以上の文での位置（文頭・文中・文末）の割合。最多の割合が 0.5 以上ならその位置が正解、未満なら「明確な正解なし」（採点から外す）。
- **主語と目的語の順序**（`so_order`）: 品詞 `VERB` の語で、子に `nsubj` と `obj`（受動の `nsubj:pass` は除く）の両方を持つものを数え、主語が目的語より前の割合を出す。0.75 以上なら `SO`、0.25 以下なら `OS`、その間は「明確な正解なし」。位置は、換字前の文の語の順（元の語順、句読点を含む）で比べる。

正解は UD の注釈から機械的に作り、著者の言語知識では決めない。

## 採点

言語ごと・割合ごとに、各項目（動詞の位置・主語と目的語の順序）を **正解・誤答・保留**（正解がない言語は「正解なし」）で数える。10%・25%・100% の 3 つの設定と、誤対応の対照で報告する。対照では、保留でない主張の件数を数える。

## 事前の予想（外れても書き換えない）

- 10% では、保留が多い。実在言語の対訳は、語彙が開いているので、同じ概念が繰り返し現れず、アラインメントが学べない。
- 100% でも、動詞の位置・主語と目的語の順序の主張は、半分以下の言語でしか出ない。
- 主張が出たものは、合成言語（LEVEL A: 動詞の位置の主張の 95% が正解）より誤答が増える。英語の文と対象の言語の文は、構造が違う（受動・名詞化・代名詞の省略）ため。
- 誤対応の対照では、主張がほとんど出ない。

## やらないこと

- 割合（10・25・100%）・閾値（0.5・0.75）・言語の選択を、結果を見て変えない。
- 結果を見て解読器を調整しない。

## 限界（事前に書く）

- 対訳は英語の文の注釈から作るので、対象の言語の文と構造が違うことがある（意訳・受動・省略）。これは実際の対訳でも起きる雑音。
- 対訳が見出し語（lemma）の列で、意味の概念ではない。英語の多義語は同じ概念として扱われる。
- 対象の言語は 19 のうち、文字の種類による除外がある。
